# 委派與回報協定

委派前確認工作可獨立完成、範圍與驗收明確。相依步驟依序執行；並行修改分配互不重疊的檔案。預設給最少必要上下文，不要求子代理重新閱讀全部文件。

## 委派格式

```text
目標：回答的問題或預期結果。
檔案範圍：允許閱讀/修改的檔案；唯讀任務明示不修改。
已知事實：主代理已確認的內容與必要背景。
驗收命令：最小測試或可觀察的完成條件。
停止條件：範圍不明、權限/SQL/核心修改、真實模型呼叫等。
協作：不是唯一編輯者，不回退他人修改，配合現有變更。
```

## 回報格式

```text
結論：已完成結果或初步歸因；推測另行標明。
證據：檔案、符號、必要行號；不貼大段原始搜尋輸出。
修改與驗證：變更檔案、命令、通過/失敗；唯讀任務填「無修改」。
未解問題：具體缺口、風險與交回主代理的決定。
```

主代理按證據整合，僅補查疑點或過時資訊。遇可驗證的新發現再擴大測試；不要反覆執行已通過且未受修改影響的檢查。成本觀察可在任務記錄中列總耗時、可取得的 Token 用量、交回次數與返工原因；沒有實際用量不估算節省比例。
