# 分錄編輯與入帳確認

辨識確認與分錄確認是兩個獨立步驟。使用者可先確認憑證欄位，即使尚未建立分錄、科目仍待核對，或借貸尚未平衡。這項確認表示憑證內容已覆核，不表示它已可納入正式帳務。

## 編輯分錄

分錄可以新增、修改及刪除。每列記錄一個科目、一個金額及借方或貸方方向；科目可手動輸入，也可參考該公司的建議。手動科目不會因此改動公司的科目表。金額為 0 是有效值；欄位缺漏時仍可保存草稿，但不能確認入帳。空白分錄列可留在草稿中，確認前須移除或補齊。

辨識明細是否存在，依單據類型或實際明細判斷；有明細的憑證仍可產生分錄。明細缺少科目或尚待核對時，不會發布品名科目共用規則，也不會阻止辨識確認。

## 使用 AI 候選

一般非會計傳票、非佐證附頁單據可選擇「產生分錄建議」。候選先供預覽、警告及證據查核，使用者可採用整組候選或捨棄。按「採用建議並替換草稿」後會比對前後內容，再確認整組替換；舊草稿保存於分錄操作歷程，不會附加而重複計算金額。候選在公司、原圖、來源欄位或品名／金額明細改變後失效；單純產生候選不撤銷既有分錄確認。

## 確認供入帳

先按「確認辨識內容」，再核對分錄並按「確認分錄可供入帳」。分錄確認需指定公司，每列都須有完整科目代碼、科目名稱、有效金額與單一借貸方向，借貸差額絕對值須小於 0.01。「以下空白//」等版面標記列必須刪除或修正；來源傳票只有單邊時可確認辨識與保存草稿，系統不補造另一面。

分錄確認後才可納入日記帳及正式傳票；這些頁面會顯示被排除的待核對憑證數，佐證附頁不計入此數。辨識明細彙總維持原有篩選條件，不要求分錄已確認。科目與金額合計由伺服器重新檢查，不以畫面顯示的平衡結果作為確認依據。

編輯或採用分錄只撤銷分錄確認。修改辨識欄位、公司、品名／金額明細或影像會撤銷兩種確認；明細會計補充欄位的修改只撤銷分錄確認。操作使用單據版本檢查，遇到其他人已更新時保留目前輸入並要求比對。確認時間採 UTC 保存，介面以台北時間顯示；操作人員取自登入帳號。

## 部署

1. 停止服務並備份 `app/data/app.db`、設定與影像資料；依實際 `config.DB_FILE` 設定確認資料庫位置。
2. 更新程式，重新執行 `start_webui.bat`。啟動時自動增加分錄狀態、確認、候選及操作歷程欄位，並為既有分錄補上固定 ID；可重複啟動。
3. 以 `Ctrl+F5` 重新載入畫面。舊辨識確認狀態不變，舊分錄先列為待核對；舊單列同時有借貸兩面的內容會拆成兩列，保留來源關聯與原始 AI 結果。
4. 人工檢視並重新確認分錄後，才會再次納入正式帳務報表。部署初期報表筆數減少代表待核對資料被排除，不表示資料遭刪除。

本次離線驗證使用合成資料、暫存 SQLite 與模擬模型，沒有呼叫真實模型或改動 gold。舊種子案例若沒有獨立分錄確認標記，不會沿用為分類案例，也不會改寫種子資料。
