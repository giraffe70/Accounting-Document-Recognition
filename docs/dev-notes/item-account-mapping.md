# 品名科目對應操作說明

品名科目對應依「公司＋正規化品名」共用；單據類型只記錄來源，不參與比對。三家公司各自維護規則，彼此隔離。同一公司不同單據類型的相同品名會共用科目。手動輸入科目不需要先修改 `accounts.json`。

## 在明細中編輯

1. 選擇公司並開啟辨識完成的憑證，在明細最左側檢視或手動輸入「會計科目」與「會計名稱」。代碼欄是文字欄位，手動科目如 `00120` 會保留前導零。
2. 每列的「記住對應」預設勾選。取消勾選後，本次仍可保存該列科目，但不建立或更新共用規則；辨識後尚未確認的新科目或不完整內容可先儲存修正，保留為待確認草稿。
3. 只有「儲存修正」、「儲存並返回」及「確認完成」會發布已勾選列的規則。重辨識、重新分類及列印暫存都不發布規則。辨識確認不要求科目完整或分錄平衡；不完整或待核對的品名科目不會發布共用規則。分錄可先保存為草稿，完成欄位與科目核對後，再另行確認分錄供入帳。
4. 更改歸屬公司或品名後，既有科目可能不適用，請重新核對。科目表依公司區分；換公司後確認科目代碼和名稱屬於目前公司。辨識確認與分錄確認分開進行；前者不代表分錄已可入帳。
5. 若儲存時偵測到憑證已有新版本，畫面會並列最新保存值與目前輸入。檢視後可繼續儲存或取消；繼續會以最新版本號重試並保留目前輸入，取消則不重試、不清除輸入，也不返回匯入頁。
6. 若品名共用規則有衝突，依畫面選擇「只修改本張」或「更新共用規則」。前者不更動現有規則；後者依所選科目建立下一版本。單據與規則衝突會先處理，再檢查憑證版本。

歷史憑證的科目是當次保存的快照。之後更新品名科目規則不會回頭修改已保存的憑證內容。

保存的明細快照在 `current_json.items` 中保留 `item_id`、`account_code`、`account_name`、`mapping_id`、`mapping_version`、`account_source`、`account_needs_review`、`remember_mapping`、`account_updated_by`、`account_updated_by_name` 與 `account_updated_at`，供檢視當次科目、規則版本及最後編輯者。後續更新規則不會回頭修改已保存的憑證快照。

相容舊端點 `PUT /api/vouchers/{rec_id}` 時，若修改明細科目，必須傳入 `expected_updated_at`。此端點只更新憑證內容，不會發布品名科目共用規則。

## 部署與驗收

第一次部署此功能前，先使用系統現有備份功能備份 `app.db` 與設定；設定備份包含 `accounts.json`、`companies.json` 等分類輸入。備份完成後完整重啟應用程式一次，讓既有資料庫遷移建立新表。

離線驗收使用 `scripts\verify.bat -Scope all`。此驗收不需要呼叫真實模型。
