# 給 H200 伺服器端 agent 的需求提示詞

> 用途：把下方「---」之間的區塊整段貼給 H200 那台機器的 AI 助手。
> 背景：本專案（憑證辨識系統）的「科目分類」階段已在用 H200 的 `qwen3-32b`，
> 現在要把「憑證影像結構化萃取」階段也從本機 Ollama 搬上去，需要一個視覺模型。

---

## 需求：在 H200 vLLM 上加開一個視覺語言模型（VLM）

我是「憑證辨識系統」專案，目前已在使用你這台 vLLM 伺服器的 `qwen3-32b` 做文字分類任務（依 `docs/api-usage-prompt.md` 的規範接入，運作正常）。現在要把另一個階段——**掃描憑證影像的欄位萃取**——也從我本機的 Ollama 搬上來，需要伺服器端提供具視覺能力的模型。以下是需求與規格，請評估並協助佈署。

### 1. 核心需求

- 加開一個 **支援影像輸入的模型**，透過 **OpenAI 相容 `POST /v1/chat/completions`** 提供服務。
- **現有 `qwen3-32b` 必須維持可用、不中斷** —— 我的分類階段還在打它，兩個模型要能同時服務。
- 我這端呼叫時送的是標準 multimodal content array，請確認伺服器能吃：

```json
{
  "model": "<新的 VL 模型 id>",
  "messages": [{"role": "user", "content": [
    {"type": "text",      "text": "……提示詞＋OCR 校對文字……"},
    {"type": "image_url", "image_url": {"url": "data:image/png;base64,iVBORw0KG..."}}
  ]}],
  "temperature": 0, "seed": 42, "max_tokens": 4096
}
```

（影像是 **base64 data URI 內嵌**，不是外部 URL —— 伺服器不需要能連外抓圖。）

### 2. 模型選擇建議

優先序如下，能上一個就好，兩個都有更佳（我想做 A/B 比較）：

1. **Qwen2.5-VL-7B-Instruct** —— 我本機現在就是跑這顆（Ollama 版 `qwen2.5vl:7b`），上到 H200 可以直接對照「同一顆模型、換到 GPU」的效果差異，是最乾淨的對照組。
2. **Qwen2.5-VL-32B-Instruct** 或 **Qwen3-VL** 系列 —— 更大顆的，想看辨識品質能不能再往上推。

H200 有 141GB HBM3e，`qwen3-32b`(BF16 ≈64GB) 再加一顆 7B VL(≈16GB) 應該有餘裕；若要上 32B VL 請評估記憶體是否需要調整現有配置。

### 3. 佈署細節（這幾點會直接影響我這端要不要改程式）

**3.1 端點 port**
- **最理想：與 `qwen3-32b` 同一個 base_url**（`/v1/models` 同時列出兩顆），我這端一行都不用改。
- 若受限於 vLLM「一個進程一個模型」而必須另開 port，請明確告知新 port，並確認 **SSH 橋接程式與防火牆規則也一併開通** —— 我這端目前只設一個 `H200_BASE_URL` 環境變數，另開 port 的話我要改成雙端點設定，請先讓我知道。

**3.2 模型 id 命名**
- 請給一個**穩定、可讀的短 id**（例：`qwen2.5-vl-7b`），不要用完整 HF 路徑。
- 原因：我的前端下拉選單直接顯示 `/v1/models` 回傳的 id，而使用者選定後**會存進設定檔當作長期設定值**。之後若 id 改名，既有設定會失效、辨識直接報錯。**上線後請勿再更動 id**，真要改請先通知。

**3.3 影像處理參數（重要，會影響辨識品質）**
- 我送的圖：**PNG，長邊 ≤1180px，總像素 <1MP**，單次請求 **1 張圖**。
- 請確認 `--limit-mm-per-prompt` 至少 `image=1`（建議設 2，我後續可能會有雙圖比對的需求）。
- **請勿把 `max_pixels` / `min_pixels` 設得太小**。我刻意把圖控在「長邊 >1000px 但總量 <1MP」，是因為我要模型回傳欄位的 **bounding box 座標**，用來在 UI 上畫「精準框」給審核人員看。伺服器若再做一次大幅降採樣，座標精度會掉、框會歪。若你們有全域的影像縮放預設值，請告訴我實際值是多少。

**3.4 context 長度**
- 單次請求約 = 影像 tokens + 2,000~3,000 文字 tokens（提示詞 + OCR grounding 文字，最壞情況是出口報單）。
- `max_model_len` 建議 **≥16384**，太小會在長單據上截斷。請告知實際值。

### 4. 呼叫參數的相容性確認（請逐項回覆）

我這端會固定帶以下參數，麻煩確認 VL 模型是否都吃得下、有沒有哪個會噴 400：

| 參數 | 值 | 想確認的事 |
|---|---|---|
| `temperature` | `0` | 貪婪解碼，要可重現 |
| `seed` | `42` | vLLM 的 per-request seed 對這顆模型是否有效？（我需要同一張憑證重跑得到同樣結果，否則分不出「改動有效」還是「這次剛好對」） |
| `max_tokens` | `4096` | 夠不夠？ |
| `extra_body.chat_template_kwargs.enable_thinking` | `false` | **這題最關鍵**：我目前對 `qwen3-32b` 都會帶這個參數關思考。VL 模型的 chat template 若不認得它，是會**靜默忽略**還是**回 400 錯誤**？若會報錯，我這端就要按模型名稱做分支處理，請明確告知。 |

### 5. 併發與健康檢查

- 沿用你們的規範：健康檢查打 `GET /v1/models`，批次併發 **≤4**。
- 但 VL 上線後兩顆模型共用 GPU，**請告知建議的併發數是否要調降**，我這端好設上限。我的使用情境是「一次匯入一疊掃描檔逐頁辨識」，會連續打，但我可以控制並行度。

### 6. 完成後請回報

麻煩給我這幾項，我這端才好改設定：

1. `base_url`（含是否與 qwen3-32b 同 port）
2. 模型 `id`（`/v1/models` 實際回傳的字串）
3. `max_model_len` 實際值
4. `seed` 是否生效
5. `enable_thinking` 參數傳過去的行為（忽略／報錯）
6. 伺服器端影像縮放上限（`max_pixels` 等實際設定值）
7. 建議併發數
8. **一段可直接執行的驗證片段**（curl 或 python，含一張小圖的 base64），讓我確認端到端通了
