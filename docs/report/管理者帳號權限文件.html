本文件說明系統的帳號種類、一般使用者與系統管理員可執行的操作範圍，以及管理員應執行的帳號維護作業。 內容依系統實際程式行為撰寫。文件日期：2026-10-27。

🚨 上線前必做
系統首次啟動會自動建立三個預設密碼的種子帳號。正式使用前務必全部變更， 變更方式見下方〈帳號維護作業〉。未變更前請勿將系統開放給實際使用者。

👥帳號類型與權限

系統區分一般使用者與系統管理員。權限在後端強制檢查（非僅隱藏畫面按鈕）， 即使直接呼叫 API 也會被擋下。

操作一般使用者系統管理員
登入系統、瀏覽憑證清單✓✓
上傳／匯入憑證、外觀確認、內容辨識✓✓
編輯欄位、影像旋轉裁切、自動分類科目✓✓
保存修正草稿✓✓

會計科目表：儲存變更—✓
地端備份與下載—✓
帳號管理（檢視、新增、編輯、停用）—✓
系統組態（模型連線、API 金鑰、掃描來源、雲端權限）—✓
修正回饋頁（檢視 AI 原始值與人工修正差異）—✓

管理權限由資料庫 users.is_admin 布林欄位記錄；帳號列表顯示管理員標記，不再儲存或顯示角色欄位。既有一般帳號名稱（包括 clerk、accountant）仍可保留，但均為一般使用者。

💡 憑證確認權限
一般使用者與系統管理員皆可完成憑證確認；管理員另可使用管理功能。

資料庫啟動遷移會將舊 admin 角色轉為 is_admin=true，其餘舊角色（clerk、accountant、other:*）轉為一般使用者，再移除 role 欄位。使用者 ID、憑證、匯入紀錄及其他資料保留。遷移完成後不相容舊版程式，部署後須重新啟動服務。

🔐安全設計

項目作法
密碼儲存PBKDF2-HMAC-SHA256、每帳號獨立隨機 salt、10 萬次迭代。 資料庫內不存明文密碼，即使資料庫外流也無法直接還原密碼。
密碼比對以定時比較（hmac.compare_digest）避免時間差攻擊。
登入憑據登入後發給隨機 session token（存於瀏覽器 cookie）。
權限檢查所有 /api 請求先驗證登入，再依管理員旗標檢查。畫面隱藏按鈕僅為輔助。
資料落地憑證影像、辨識結果、科目表皆存於本機，不上傳雲端。
⚠️ 現況限制（請留意）
  • 登入階段存於記憶體：伺服器重新啟動後所有人需重新登入。管理員停用帳號後，該帳號禁止登入，且其既有 session 會在下次請求時失效；其他帳號不受影響。
  • 系統未強制密碼定期更換、未鎖定連續登入失敗。若貴公司資安政策有此要求，屬設計變更項目。
  • 帳號每次使用 session 時都會重新核對資料庫中的啟用狀態與管理員旗標。
  • 管理員可在網頁編輯帳號名稱、顯示名稱與密碼；CLI 也可變更密碼與顯示名稱。一般使用者不可自行取得管理權限。
  • 契約載明本次開發具備帳號密碼登入等基本資安防護；第三方弱點掃描與滲透測試不在範圍內。

🛠️帳號維護作業

網頁管理帳號

登入後，管理員可由右上角「權限管理」開啟 /users.html。所有管理員都能檢視帳號及啟用狀態、新增、編輯與停用帳號。新增欄位只有帳號、顯示名稱、密碼及確認密碼；新增帳號一律為一般使用者。密碼至少 8 字元，且拒絕預設或常見密碼。

管理員可編輯啟用或已停用帳號的帳號名稱、顯示名稱與密碼；密碼欄留白表示不變更密碼。更改密碼會使該帳號所有既有 session 失效；若更改自己的密碼，須重新登入。編輯保留使用者 ID、憑證及匯入紀錄等歷史關聯資料。網頁不提供授予管理權限的功能。

停用帳號會保留帳號及所有歷史關聯資料，不允許登入，並使該帳號的既有 session 失效。不可停用自己的帳號或最後一個啟用中的管理員。停用帳號目前使用的名稱仍受保留，不可用相同名稱重新新增。

帳號管理 API 為 GET/POST /api/users、PATCH /api/users/{id} 及 DELETE /api/users/{id}，僅管理員可使用；POST 不接受 role 或 is_admin。

伺服器端 CLI 維護

於伺服器主機開啟命令提示字元，切換至系統資料夾後執行。CLI 的 list/add/delete 與網頁共用帳號規則，也提供 passwd/rename 指令。所有密碼皆以互動方式輸入，不會顯示於畫面、也不會留在命令歷史紀錄中。

檢視所有帳號（含是否仍為預設密碼）

指令
python scripts/manage_users.py list
輸出範例
帳號              管理員       顯示名稱            啟用狀態       密碼狀態
admin           是           系統管理員           啟用          ⚠ 仍為預設密碼
clerk           否           clerk               啟用          已變更
accountant      否           accountant          已停用        已變更

變更密碼（上線前所有預設帳號都要做）

指令
python scripts/manage_users.py passwd admin

系統會要求輸入兩次新密碼。密碼至少 8 字元，且不接受常見或預設密碼；變更後該帳號所有既有登入失效，須重新登入。

新增帳號（CLI）

指令
python scripts/manage_users.py add wangms 王小姐
python scripts/manage_users.py add --admin wanglead 王主管

一般使用者格式為 add <帳號> <顯示名稱>；新增管理員使用 add --admin <帳號> <顯示名稱>。既有的 admin 帳號仍是管理員；舊 clerk、accountant 帳號名稱保留為一般使用者。

更改顯示名稱／停用帳號（CLI）

指令
python scripts/manage_users.py rename wangms 王大明
python scripts/manage_users.py delete wangms

delete 會停用帳號，不會刪除帳號資料；需輸入 yes 二次確認。系統會阻止停用最後一個啟用中的管理員帳號，避免無人可管理。停用後保留歷史關聯、禁止登入且既有 session 下次請求失效；帳號名稱仍保留，不可重新新增。

🛠️ 建議的帳號規劃
  • 實際使用者各自使用專屬帳號，不要共用；系統的修正紀錄以帳號區分責任。
  • admin 帳號僅供系統維護（改設定、備份、管理帳號），日常記帳請用個人帳號。
  • 人員離職時請以網頁或 CLI 的 delete 停用帳號；歷史資料會保留。需要改密碼或顯示名稱時，可使用網頁編輯功能或 CLI 的 passwd、rename。

💾備份與還原

備份為管理員專屬功能，於系統畫面右上角「💾 備份」執行。

項目說明
備份內容資料庫（憑證、辨識結果、審核紀錄、帳號）與設定檔（會計科目表、公司登錄、模型設定），打包為 zip。
備份位置本機系統資料夾內，可從畫面下載後另存至貴公司指定的儲存媒體。
建議頻率每月結帳完成後至少一次；重大調整（如大量匯入、科目表變更）前後各一次。
還原方式將 zip 內容還原至系統資料夾後重新啟動。還原會覆蓋現有資料，執行前請先備份當下狀態。
⚠️ 備份檔含機密資料
備份檔內含完整憑證影像與財務資料，以及帳號密碼雜湊值。請比照財務文件保管， 勿存放於未加密的共用空間。
